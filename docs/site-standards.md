# QSM 网站长期编辑与验收规范

更新日期：2026-10-08。适用于网站页面、网页 Notebook、下载 Notebook 与练习包；原始推文的署名与出版格式按 articles 下规则处理。

本规范记录用户明确提出的长期要求。当前网页整改方案见 [2026-10-07 修改备忘录](../Task/site-review-20261007/修改备忘录-待审核.md)，用户已于 2026-10-07 批准实施，并选择顺序语义 URL。三章标题固定为 M1：无通勤基准模型、M2：加入跨地区通勤、M3：通勤成本变化。

## 1. 教学主线与独立阅读

- 每个模型页用完整导语交代本页问题、继承的假设、改变的条件与学习目标。不能只用一句抽象概述代替初学者所需的框架。
- 后续页区分机制扩展、基准变化和政策变化。换用非对称基准或新政策不等于新增行为机制。
- 读者单独收到一页链接，也应知道前置内容、当前模型位置和下一步；用标题、可点击学习路径和相邻页链接共同说明。
- 不把不同基准下的跨章数值差异直接解释为机制效应。基准、校准、识别、政策内固定量和福利对象必须明确。
- 内部 P 编号不用于面向读者的图示和标题；M1/M2/M3 是已批准的公开教学序号，发布后保持稳定。

## 2. 页面头部

- 短标题准确表达模型或主题，解释放在 2–3 句完整导语中。导语长度按内容需要，不强求所有页面在手机上只有两行。
- 模型章节统一提供：系列位置、实际可用的下载资源、适合读者和先修、学习目标、离线运行说明。
- 不为形式一致而虚构数据、Notebook、完整练习包或估计环节。
- 页面及下载 Notebook 不显示作者、邮箱、Title、Keywords；不重复放置已有全站导航。顶部学习资源链接保留。
- 标题上下保持约半行正文高度的留白，跨页一致。

## 3. 导航与网址

- Part/侧栏分组使用简短一致的名称，与顶部对应菜单一致；用样式加粗，不往标签写 Markdown 星号。
- URL 采用稳定英文名称；不能仅因短标题调整而擅自改 URL。
- 本次统一发布前，按用户指令直接迁移为 `m1-baseline.html`、`m2-commuting.html`、`m3-transport-policy.html`，不生成旧页面或跳转；同步站内引用、下载入口和检查脚本。
- 统一发布后，网址和公开教学序号保持稳定。确需迁移或改动已有深链接时，先制定兼容方案再获批准；此项仅适用于已发布网址。

## 4. 代码与读者文案

- 网页 Python 代码默认折叠，普通示例围栏也包括在内；文字和箭头显眼但不抢正文。支持鼠标、键盘和清晰焦点，展开状态不能只依靠颜色判断。
- 结果保留在对应计算附近；只折叠代码不隐藏关键结果。Agent 提示词采用独立的分类折叠卡片，默认收起；左侧为类别图标，右侧为展开箭头，展开后可复制，与绿色 Python 代码入口区分。
- 正文解释数据的经济含义、运行后看哪里、结果为什么成立。路径回退、哈希、诊断字段放到操作说明、可展开区域或代码注释，必要的复现与经济核验不删。
- 私人环境名、沙箱故障、内部任务状态和开发过程放入 Task/logs；公开排错写适用范围与读者可执行步骤。
- 不把一章的数据读取、参数估计、脚本选项或样本量推广为全站通则。

## 5. 公式与交叉引用

- 教学陈列公式须具备统一编号和稳定语义标签，能够从正文跳转引用；行内变量和短式通常不编号。
- 采用页内自动编号，跨页引用写章节名称；多行方程组默认共用编号；不手工硬编码当前位置数字，不对提示词与代码内部表达式机械编号。
- 修改格式后既检查语法渲染，也核对数学含义、上下标及乘数，防止合法语法掩盖错误。

## 6. 图片

- 所有实质教学图具备图号、图名、替代文本、来源或教学构造说明；Notebook 输出图也适用。Logo 与装饰图不编入教学图序列。
- 默认点击在页面内放大查看，不触发下载或离开当前阅读页；验证关闭、Esc、焦点返回和手机阅读。
- 不因原图带 attachment 响应头而修改图床配置；优先复用站点的图片查看组件。
- 密集图优先与正文同宽，保持纵横比；不能用统一 640px 上限压小全部图片。低分辨率图先检查实际清晰度，不盲目放大。
- 本站图号与原论文图号分别表达；清理手写图号后再启用自动编号，避免重复。

## 7. 表格

- 常规数据与结果表在桌面与正文栏同宽。验收实际列区和数据行，不仅检查外框宽度。
- 文字左对齐、数值右对齐，表头有单位，小数位按变量统一；保留有意义地区/情景标签，隐藏无意义自动行索引。
- 手机使用外层滚动容器，保持字号与列的可读性，不造成整页溢出或逐字竖排。
- 正文明确指出要读哪一行/列及经济含义。所有正文教学表和计算结果表均设表名、页内自动编号和稳定锚点。

## 8. FAQ 与新增章节联动

- FAQ 面向全站，至少覆盖学习路线、模型、识别与解释、代码运行、文献；按问题性质分类。
- 每增一章，检查 FAQ 是否需要增加、修订或标注适用范围；移除过时的“尚未实现/后续计划”状态。
- 文献问题区分教学模型、论文机制、真实数据识别和复现要求；不把教学结果归给原论文。

## 9. 同步与验收

- 保持已确定的单一内容来源。网页与离线 Notebook 可因相对资源路径不同而采用明确的转换，不能只靠文件大小判断同步；检查正文、公式、代码、输出和链接。
- Markdown/CSS 编辑通常不需重复数值求解；计算代码或数据变化须按模型规则重新运行。新建离线包必须在新目录实际验证。
- 维护规则变更时同步检查自动验收契约，避免已删除的旧头部词语仍被要求存在。检查脚本应只读，生成与修改必须是显式入口。
- 验收包括：构建、站内链接、无废弃网址残留、图式编号/交叉引用、代码展开操作、图片点击不下载、实际表格列宽、桌面与手机视觉、下载与离线包、模型/代码保护。
- 只验证 HTML 元素存在或 CSS 外框尺寸不足以代表阅读体验达标。
- 用户要求先提方案时，只更新备忘录与被明确授权的规则文档，不修改网页、样式、计算文件或发布材料。发布仍需单独授权。

## 10. 实现与新增页契约

公式、图形和表格均采用 Quarto 原生交叉引用；表格涵盖 Markdown 与 Notebook HTML 输出。表格身份由语义标签确定，不把显示位置当作长期锚点。新增表格必须提供标题与稳定标签，检查器应拒绝缺失。

执行 Notebook 后运行 `python site/prepare_site.py`，按单元的 `qsm_tables` 元数据恢复输出表标题、同步离线副本和 ZIP，并转换 M1 的网页 QMD。该脚本不计算模型；网页引用与离线路径可不同，代码和数值应相同。

## 11. 随读 Agent 提示词：两类任务

本节与第 12–13 节为用户已确认的长期规则。2026-10-07 已按此规范完成页面、指南与资源迁移；后续新增内容继续遵守相同验收要求。

### 11.1 目的与分类

提示词帮助读者明确研究问题、模型约束、输入材料、交付物和核验条件，逐步从讲义练习转向自己的研究。两类名称固定：

| 类型 | 用途 | 内容要求 |
|---|---|---|
| 讲义练习 | 复现、理解或扩展当前教学模型 | 使用具体设定，提供材料链接，尽量直接复制使用 |
| 迁移到我的研究 | 将任务方法用于读者的研究 | 使用 `{……}` 占位符，给出填写示例、适用条件和检查要点 |

- 卡片跟随模型设定、校准、求解、政策比较和核验出现，不集中堆在章末，也不要求每个位置成对出现。不规定固定数量。
- 标题同时显示 Agent、类型和具体任务；默认折叠。讲义练习采用浅紫底与书本标记，迁移任务采用浅蓝底与向外箭头；颜色和图标不表示难度或重要程度，相邻卡片不代表必须连续执行。
- 长期保留完整实现任务书作为讲义独立实现练习；随读卡片与完整任务书的用途要说清楚。

### 11.2 材料与可迁移性

- 统一使用指南说明五类材料：研究问题、模型设定、数据口径、已有程序与结果、本次任务及验收要求。按任务提供，不要求初学者一次准备完整项目。
- 每个模型章提供指南入口；下载材料包含离线说明。指南允许只有研究想法的读者先整理待确定的模型条件，不让 Agent 擅自填补关键假设。
- `model.md` 只是本站模型说明文件的文件名，读者可以用自己的文本、文档或论文相关段落。讲义练习在材料区提供具体下载链接，复制文本明确说出任务所依赖的模型，不能只写本章或上一章。
- 迁移任务的复制文本不得依赖本章、本站、M1/M2/M3 等网站指代，也不固定要求名为 model.md 的文件。示例区允许展示教材文件名与教学编号。
- 占位符采用 `{模型说明材料}`、`{政策变化}` 等有含义的名称；每个占位符在材料区说明应填写什么。无需材料的项目可明确填无；不能留给 Agent 猜测。步骤、约束和检查要求写具体，不把整段任务变成空格表。
- 模板与填写示例分开呈现、分别复制。复制按钮只复制对应任务块，不夹带标题、检查说明或另一段示例。新会话必须重新提供相关材料；不假定 Agent 已读过网页、已打开链接或继承其他会话上下文。

### 11.3 学术边界与执行证据

- 每张卡片说明用途和适用条件，列出所需材料、一个可复制任务及拿到回复后应检查什么。迁移类另给简短填写示例。
- 两地区求解、解析解、福利公式、对称性、校准方式和特殊情形检验都须标明条件，不能仅换参数名就称为通用模板。
- 区分改变政策力度与改变机制；区分给定、估计与校准参数；区分政策内固定基本面与参数敏感性下的基准重建。不得把某章规则推广为全部 QSM 的共同规则。
- 区分阅读代码、从零独立实现和已有程序修改。只有独立实现练习要求新目录、新会话及不读参考答案；日常修改允许使用已有程序。
- 缺少条件时列出缺口，不编造数据、参数或运行结果。无法实际运行时，明确区分建议步骤与已完成检查。
- 模型理解、识别判断和结果解释由研究者负责。数值检查不证明一般唯一性或真实政策有效；基准拟合不等于识别。
- 内容审阅、参考代码运行、Agent 独立实现是不同证据；未进行新一轮独立实现不得声称通过试跑。

### 11.4 内容来源与下载

- 主 Notebook 是随读卡片唯一编辑源。生成 guided-prompts.md、下载 Notebook 和压缩包，不单独编辑生成副本。
- 统一指南以 site/pages/agent-guide.qmd 为来源；网页 agent-guide.html 与各包 prompts/usage-guide.md 经明确转换同步。网页与下载包由同步脚本生成，检查器比较指南源稿与离线正文。
- 完整练习包与独立输入包继续区分。后者可含模型、数据、指南和提示词，不得加入 Notebook、参考程序或政策答案。
- 改版必须同步学习路线和 FAQ。跨站分类规则作用于新旧卡片，但不自动改写已确认的原始推文。

## 12. 全站语义配色

机器可读色值集中记录在 site/prompt-contract.json，按用途定义 CSS 变量；不在各卡片任意添加颜色。修改色值时同时更新本表、配置和验收记录。

| 用途 | 强调色 / 文字 | 浅背景 | CSS 变量前缀 |
|---|---|---|---|
| 正文与主基调 | #102A43 | #FFFEFA | --qsm-body |
| 次要说明 | #55707E | #FFFEFA | --qsm-muted |
| 说明与模型设定 | #34566B | #F0F4F7 | --qsm-note |
| 操作与 Python | #176A72 | #EDF5F3 | --qsm-action |
| Agent 讲义练习 | #71528C | #F7F3FA | --qsm-exercise |
| Agent 迁移到我的研究 | #245D83 | #EDF4FA | --qsm-transfer |
| 注意与解释边界 | #875A24 | #FBF4E8 | --qsm-warning |
| 实际错误与阻断 | #983E46 | #FAEFF0 | --qsm-error |

- 每个前缀使用 -fg、-bg 后缀；--qsm-focus 固定为 #176A72。主导航与标题保持深海军蓝，米色辅助面保留 #F7F4ED。
- 颜色集中用于标题条、左边框与标记，展开后的长正文保持白底深字。普通正文文字对背景对比度目标不低于 4.5:1；浏览器核对实际计算样式，不能仅凭声明认定合格。
- Quarto note 对应说明；tip 对应操作；warning 对应解释边界；caution 对应实际错误。important 不默认映射红色，应根据真实含义人工归类，普通强调优先使用正文。
- 普通说明和核心假设、解释边界默认展开；Python 与 Agent 默认收起。Python 保留原生箭头；Agent 左侧图标固定表示类别，右侧箭头随开合改变，不再使用两类共用的加减号。非交互标题不显示折叠标记。
- 颜色、类别图标和文字共同区分类别。红色只用于实际错误；不使用颜色深浅区分两类 Agent。
- 链接青绿色并保留可识别的链接样式；复制按钮随所属卡片强调色；焦点统一青绿色。复制成功和失败同时提供准确文字反馈，不以颜色代替状态。
- 表格、图注及代码底色使用中性色，保留必要的代码语法高亮。科研图表的颜色按数据含义和图例另行设计，不机械套用提示框的语义色。
- 新页复用全站样式，不新增每章专属配色。现有字号、图式表编号、图片查看和手机滚动规范继续生效。

## 13. 新版规范验收与迁移顺序

先固定规则与只读检查工具，再改指南、卡片、共享样式和资源同步，最后全站验收。不得为了使旧页面通过而弱化新规则。

- `python site/check_site.py`：现有页面检查，明确提示尚未检查新版提示词规范。
- `python site/check_site.py --prompt-contract audit`：现有检查加新版缺口盘点；新版缺口不会使 audit 失败，但必须显示 PENDING，不能当作新版通过。
- `python site/check_site.py --prompt-contract strict`：现有检查加新版静态验收；任何缺口返回非零状态。CI 已采用此命令，后续发布前仍须本地执行。
- `python site/check_prompt_contract.py --audit --json`：仅输出新版盘点 JSON；默认不带 --audit 为严格模式。检查器只读，不调用生成脚本、不联网、不运行模型、不写入站点。
- 自动检查覆盖分类、默认折叠、结构字段、占位符声明、迁移文本中的明显网站依赖、源稿与渲染及下载任务一致性、资源和压缩包同步、颜色变量声明及理论对比度。
- 人工审阅覆盖：仅提供声明材料的新会话可理解性、经济学适用条件、材料链接是否足以完成任务、实际复制与焦点操作、390 px 展开布局、实际颜色及整体阅读体验。
- 静态通过不等于人工审阅或独立试跑通过。既有代码、公式与结果的保护比较须单独记录；仅编辑文案和样式不重复求解。

组件约定、测试命令与各类证据的边界见 [维护说明](../site/README.md)。
